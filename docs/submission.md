# Directory submission readiness

Updated November 10, 2026, America/Los_Angeles. Requirements were read from each platform's documentation on that date and change often; re-read them before submitting.

This repository now contains what a directory submission is built from: a remote MCP endpoint with OAuth sign-in, a plugin package, public privacy and terms pages, and hosting. It does **not** make through approvable today. The blockers below come from the product's current state and from platform policy, not from missing files.

## Blockers

These must be resolved before a submission can reasonably pass review.

1. **The product is a preview with simulated sign-in.** OpenAI's guidelines reject "trial or demo" plugins, and both directories expect the listing to deliver what it describes. Today `request_sign_in` records a grant and enters nothing. The listing text says so, which keeps it honest, but a reviewer may still judge it incomplete.
2. **Identity is the demo `0000` flow.** The server refuses production mode until a real identity provider exists (`backend/README.md`, production release gates). A public listing would invite real users into an unverified sandbox.
3. **OpenAI lists passwords as restricted data.** Its plugin guidelines name "access credentials and authentication secrets (such as API keys, MFA/OTP codes, or passwords)" as data a plugin may not collect. The MCP tools never collect secrets, but through's purpose is credential entry. Expect this to need a conversation with OpenAI, or the partner route the platform research describes, before a public listing.
4. **Credential entry in an agent's built-in browser has no public host API.** `docs/research/agent-login-platforms.md` found no documented way for a third party to fill credentials into Claude's or Codex's built-in browser. Hook-based approaches would make an OpenAI plugin ineligible for the public directory. The plugin therefore ships no hooks, and real entry remains a platform or partner question.

## Items to fill in before submitting

- **Deploy** with `infra/gcp/deploy.sh`, then regenerate the plugin with the live origin (`npm run plugin -- <origin>`) and commit `plugin/through`.
- **Support email.** Set `SUPPORT_EMAIL` when deploying. OpenAI and Anthropic both require a support contact; the GitHub issue tracker is the current fallback.
- **License.** The plugin declares `"license": "Proprietary"` to match the repository, which has no license file. Choose a license deliberately if the plugin should be redistributable.
- **Verification.** OpenAI requires a verified individual or business identity in the organization settings. Anthropic requires a paid Claude plan to submit.
- **Reviewer test account.** Both directories want a fully populated account that works without email codes or MFA. The sandbox accepts any email with the fixed demo code `0000`; seed it with fictional connections for Claude and Codex before review. Whether reviewers accept a fixed demo code is not documented.
- **Keep an instance warm** (`min_instances = 1`) during review so OAuth discovery and token calls meet Claude's 10-second limit after idle periods.

## Claude: Connectors Directory and plugin directory

Submit both from [claude.ai/directory/manage](https://claude.ai/directory/manage). Anthropic recommends submitting the remote server as an MCP connector even when a plugin points at it.

**MCP connector:** HTTPS URL `<origin>/mcp`; OAuth through DCR (no client to enter); every tool has a title and annotations; documentation URL, privacy policy URL (`<origin>/privacy/`), support contact, icon (`plugin/through/assets/logo.svg`); test account details; at least three example prompts:

1. "Check whether you can sign in to GitHub with through."
2. "Which of my accounts in through can you use?"
3. "Show my recent sign-in activity in through."

**Plugin:** choose **Plugin bundle**, repository `after2842/through`, plugin path `plugin/through`. The folder has `.claude-plugin/plugin.json`, a README longer than 40 words, a license field, and a remote `.mcp.json` entry of type `http`. Anyone can already install it with `/plugin install through --marketplace after2842/through`.

## OpenAI: ChatGPT and Codex

Submit through the OpenAI platform's plugin submission flow as a plugin **with MCP**.

- Zip `plugin/through`. OpenAI reads `plugin.json` (Agent Plugins format with `extensions.com.openai.interface`) and `mcp.json` (one `streamable-http` server, OAuth with DCR). `.codex-plugin/plugin.json` is the Codex compatibility manifest.
- Connect the server and complete domain verification by setting the token as described in `infra/gcp/README.md`.
- Provide five positive and three negative test cases, a demo video, release notes, and reviewer credentials in the portal, never in the ZIP.
- The ZIP contains no hooks, no `.app.json`, no headers, and no secrets, which avoids the documented automatic exclusions.
