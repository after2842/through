## Test data and failure recovery

Use two synthetic tenant identities and fictional provider account references. Do not type real provider passwords or OTP seeds into any demo. Verify failures through the public HTTP contract and persisted database state, not by checking UI text alone.

For network failure, keep the account selection and let the user retry. For an expired through session, clear stale client state and return to login. For a denied or revoked grant, show the reason and require new authorization. For an uncertain external fill, record the outcome as unknown/action-required; do not infer success from an HTTP 200 or automatically submit credentials again.
